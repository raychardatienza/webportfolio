# Raychard Atienza: Portfolio

A static portfolio site: HTML, vanilla JavaScript and a precompiled Tailwind stylesheet. All paths are relative, so it works from a domain root (Hostinger `public_html`) and from a GitHub Pages subpath (`username.github.io/portfolio/`).

```
index.html                     ← main page markup
assets/js/main.js              ← all content data (projects, timeline, charts, notes, testimonials) and behaviour
notes/                         ← technical articles
.htaccess                      ← Hostinger: HTTPS, security headers, caching (GitHub Pages ignores it)
case-studies/pdmis.html        ← PDMIS case study
404.html                       ← themed "route not found" page (GitHub Pages and Hostinger use it automatically)
assets/css/styles.css          ← compiled stylesheet (generated, don't edit by hand)
assets/fonts/                  ← self-hosted variable fonts (Inter, Space Grotesk, JetBrains Mono)
assets/resume/…Resume.pdf      ← generated from _src/resume.html
assets/images/og-image.png     ← link-preview card (generated from _src/og-image.html)
assets/images/projects/*.svg   ← project illustrations (generated by _src/project-art.js)
assets/icons/                  ← favicons and app icons
assets/certificates/           ← CPMS / CASM / CPSCA certificate PDFs
_src/                          ← sources: input.css, resume.html, og-image.html, icon.html, project-art.js,
                                 github-profile-README.md, old-portfolio-redirect.html
tailwind.config.js             ← Tailwind theme and the files it scans
robots.txt, sitemap.xml, site.webmanifest, .nojekyll
```

## Personal brand, not an agency site

This is a personal portfolio. NCIP appears only where it is factual employment history: the Experience timeline, the career chart and the resume. Everywhere else, projects are labeled as public-sector work, and the illustrations carry a neutral `GOV` badge. Keep it that way when you add content.

## Rebuild the CSS after changing classes

The site uses the small compiled `assets/css/styles.css`. Rebuild it whenever you add or change Tailwind classes in `index.html`, `assets/js/main.js`, `case-studies/` or `notes/`, or edit `_src/input.css`:

```powershell
cd C:\Users\Administrator\Desktop\Portfolio
npx tailwindcss@3.4.17 -i ./_src/input.css -o ./assets/css/styles.css --minify
```

Text-only edits (wording, dates, links) don't need a rebuild.

## Regenerate the resume, preview image, illustrations or icons

```powershell
$chrome = "C:\Program Files\Google\Chrome\Application\chrome.exe"
# Resume PDF (edit _src/resume.html first)
& $chrome --headless=new --no-pdf-header-footer --print-to-pdf="$PWD\assets\resume\Raychard-Atienza-Resume.pdf" "$PWD\_src\resume.html"
# Link-preview image (1200×630)
& $chrome --headless=new --hide-scrollbars --allow-file-access-from-files --window-size=1200,630 --virtual-time-budget=6000 --screenshot="$PWD\assets\images\og-image.png" "$PWD\_src\og-image.html"
# Project illustrations
```

To add an illustration for a new project, add an entry in `_src/project-art.js`, regenerate, and point the project's `image:` in `index.html` to the new `.svg`. A real screenshot (`.jpg` or `.png`) also works.

## Signature features

- **Archipelago hero:** the Philippines drawn as a live data network, with pulses traveling from Quezon City. The coastline is simplified from Natural Earth 1:50m (public domain); outlines, cities and the home marker are the `ISLANDS`, `HUBS` and `HOME` constants in `assets/js/main.js`.
- **Terminal:** press `/` (or click `›_` in the nav). Commands live in `COMMANDS` inside `setupTerminal()`; add your own there.
- **Boot intro:** plays once per browser session, about 1.4 seconds, and any key or click skips it. The text lines are in `runBoot()`.
- **Page transitions** between the portfolio and the case study use the browser View Transitions API. Browsers without it just navigate normally.
- **Scroll-driven case study:** on desktop, the PDMIS workflow document moves through each step as you scroll.

## Personal touches

- **Personalized links:** send `…/portfolio/?for=Acme` and the hero greets "Acme", the page title names them, and the contact subject is pre-filled. Add `&focus=react` (or any tech, `gov` or `web`) to put matching projects first.
- **English / Filipino:** the `FIL` / `EN` button in the nav switches the hero, About, "why this work" and Contact text. The Filipino strings are in `I18N_FIL` in `assets/js/main.js`; have a native speaker review them, and add an element by giving it `data-i18n="key"` plus a matching entry.
- **Terminal `ask`:** visitors can type questions like `ask why public sector`. Answers and their keywords are in `ANSWERS` in `main.js`.
- **Impact numbers:** fill `IMPACT` in `main.js` (value, suffix, label, note) and a "Results, in numbers" section appears above Insights.
- **Live demo card:** the Laravel demo lives in `Desktop/approval-workflow-demo`. After deploying it or pushing it to GitHub, set `DEMO_LINKS` in `main.js`, and it appears first in Selected work.
- **Design system:** `design-system.html` documents the colors, type, components and motion rules, linked from the footer. To bring it into Figma, open it in Chrome and use the Figma Chrome extension or the html.to.design plugin.

## Before you deploy

1. **Contact form:** get a free access key at <https://web3forms.com> using `raychardatienza@gmail.com`, then paste it into `WEB3FORMS_ACCESS_KEY` at the top of `assets/js/main.js`. Until then, the form opens the visitor's email app.
2. **Site URL:** link previews, the sitemap and search engines need the full address. Everything assumes `https://raychardatienza.github.io/portfolio/`. If you deploy elsewhere (for example a custom domain), find and replace that URL in `index.html`, `case-studies/pdmis.html`, `robots.txt`, `sitemap.xml`, `_src/og-image.html` and `_src/github-profile-README.md`.
3. **Check the content:** the descriptions of DRIP, COC, IPS/IPO and the SSO site, the expansions of COC, IPS and IPO, and the tech stack for each public-sector system, other than PDMIS which was confirmed from its source code.
4. **Employer clearance:** confirm with your agency that describing these internal systems and the PDMIS case study publicly is allowed.

## Notes (articles)

Articles live in `notes/`. To add one, copy an existing note, change the text, add an entry to `NOTES` in `assets/js/main.js`, and add its URL to `sitemap.xml`. Code blocks go inside `<pre><code>…</code></pre>`; write `<` as `&lt;`, `>` as `&gt;` and `&` as `&amp;`. Review the two included articles before publishing, since they go out under your name.

## Old portfolio redirect

`_src/old-portfolio-redirect.html` sends visitors from `raychardatienza.github.io/webportfolio/` to the new site. In the old `webportfolio` repository, replace `index.html` with this file and push.

## Hostinger security headers

`.htaccess` forces HTTPS and adds security headers (HSTS, a content security policy, no framing, nosniff) plus caching and compression. Upload it with the site; it's a hidden file, so enable "show hidden files" in the File Manager. Check the result at <https://observatory.mozilla.org>. If you add a new external service (for example another analytics tool), allow its domain in the `Content-Security-Policy` line.

## Visitor stats (optional)

There is a commented-out GoatCounter snippet in the `<head>` of `index.html`. GoatCounter is free and cookie-free. Create an account, replace `YOURCODE`, and uncomment it.

## Editing content

Projects, the experience timeline, the training list and the notes are plain arrays (`PROJECTS`, `TIMELINE`, `TRAINING`, `NOTES`) in `assets/js/main.js`:

- `featured: true` puts a project in the horizontal **Selected work** gallery.
- `cat: 'eng'` puts a project in the collapsed **Archive** instead of the main grid.
- `links: [{ label, href, icon, internal }]` adds buttons. `internal: true` opens in the same tab.

The **Insights** charts read from `CAREER`, `CAREER_MILESTONES`, `TRAINING_HOURS` and `SYSTEM_ERAS`. "Most-used technologies" and "Portfolio by discipline" are calculated from `PROJECTS`. The chart colors (`--c-gov`, `--c-web`, `--c-eng`, `--c-seq`, `--c-emph` in `_src/input.css`) were checked for colorblind safety in both light and dark mode.

## Deploy

- **GitHub Pages:** push this folder to a repo named `portfolio`, then go to *Settings → Pages → Deploy from branch → `main` / root*.
- **Hostinger:** upload the folder contents into `public_html`.
- **Preview locally:** double-click `index.html`, or run `npx serve .`. Fonts are self-hosted, so it works offline too.
