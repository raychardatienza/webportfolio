# Raychard Atienza: Portfolio

A static portfolio site: HTML, vanilla JavaScript and a precompiled Tailwind stylesheet. All paths are relative, so it works from a domain root (Hostinger `public_html`) and from a GitHub Pages subpath (`username.github.io/portfolio/`).

```
index.html                     ← main page (projects, timeline and chart data live in the <script> at the bottom)
case-studies/pdmis.html        ← PDMIS case study
assets/css/styles.css          ← compiled stylesheet (generated, don't edit by hand)
assets/resume/…Resume.pdf      ← generated from _src/resume.html
assets/images/og-image.png     ← link-preview card (generated from _src/og-image.html)
assets/icons/                  ← favicons and app icons
assets/certificates/           ← CPMS / CASM / CPSCA certificate PDFs
_src/                          ← sources: input.css, resume.html, og-image.html, icon.html
tailwind.config.js             ← Tailwind theme and the files it scans
robots.txt, sitemap.xml, site.webmanifest, .nojekyll
```

## Rebuild the CSS after changing classes

The site no longer loads Tailwind from a CDN; it uses the small compiled `assets/css/styles.css`. Rebuild it whenever you add or change Tailwind classes in `index.html` or `case-studies/`, or edit `_src/input.css`:

```powershell
cd C:\Users\Administrator\Desktop\Portfolio
npx tailwindcss@3.4.17 -i ./_src/input.css -o ./assets/css/styles.css --minify
```

Text-only edits (wording, dates, links) don't need a rebuild.

## Project illustrations

The neon line-art images in `assets/images/projects/*.svg` are generated by `_src/project-art.js`. Each project has its own entry there, so you can tweak a drawing, or add one for a new project, and regenerate:

```powershell
node _src/project-art.js
```

Then point the project's `image:` in `index.html` to the new `.svg`. A real screenshot (`.jpg` or `.png`) also works.

## Before you deploy

1. **Contact form:** get a free access key at <https://web3forms.com> using `raychardatienza@gmail.com`, then paste it into `WEB3FORMS_ACCESS_KEY` near the bottom of `index.html`. Until then, the form opens the visitor's email app.
2. **Site URL:** link previews, the sitemap and search engines need the full address. Everything assumes `https://raychardatienza.github.io/portfolio/`. If you deploy elsewhere (for example a custom domain), find and replace that URL in `index.html`, `case-studies/pdmis.html`, `robots.txt`, `sitemap.xml` and `_src/og-image.html`.
3. **Check the content:** the descriptions of DRIP, COC, IPS/IPO and the SSO site, the expansions of COC, IPS and IPO, and the tech stack for each NCIP system, other than PDMIS which was confirmed from its source code.
4. **Agency clearance:** confirm with NCIP that listing these internal systems and the PDMIS case study publicly is allowed.

## Editing content

Projects, the experience timeline and the training list are plain arrays (`PROJECTS`, `TIMELINE`, `TRAINING`) in `index.html`:

- `featured: true` shows a project on the default tab.
- `cat: 'eng'` puts a project in the collapsed **Archive** instead of the main grid.
- `links: [{ label, href, icon, internal }]` adds buttons. `internal: true` opens in the same tab.

The **Insights** charts read from `CAREER`, `CAREER_MILESTONES`, `TRAINING_HOURS` and `SYSTEM_ERAS`. "Most-used technologies" and "Portfolio by discipline" are calculated from `PROJECTS`. The chart colors (`--c-gov`, `--c-web`, `--c-eng`, `--c-seq`, `--c-emph` in `_src/input.css`) were checked for colorblind safety in both light and dark mode.

## Deploy

- **GitHub Pages:** push this folder to a repo named `portfolio`, then go to *Settings → Pages → Deploy from branch → `main` / root*.
- **Hostinger:** upload the folder contents into `public_html`.
- **Preview locally:** double-click `index.html` (fonts need internet), or run `npx serve .`.
