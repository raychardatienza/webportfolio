[01] // the problem

Planning documents that travel between offices.

An agency project passes through several documents before money is spent: a Mother Project Proposal (MPP), Activity Designs, Work and Financial Plans (WFP) at agency, regional and program level, a Project Procurement Management Plan (PPMP) and the consolidated Annual Procurement Plan (APP).

Each one is reviewed, commented on, returned for revision, recommended, approved and signed by different people. When that happens in spreadsheets, email and paper, nobody can see where a document is, who last touched it, or whether a printed copy is genuine.

Architecture Impact // Before & After

From Fragmented Spreadsheets to Event-Driven State Machine

✕ BEFORE: Legacy Paper & Spreadsheets
  • •Turnaround: 2 to 3 weeks average per document routing cycle.
  • •Visibility: Zero real-time tracking; manual phone follow-ups across regional offices.
  • •Discrepancies: Formula calculation errors and budget ceiling mismatches caught late.
  • •Verification: Physical wet signatures vulnerable to alteration without audit log.
✓ AFTER: PDMIS Laravel 12 Monolith
  • •Turnaround: Under 4 hours for multi-stage technical reviews.
  • •Visibility: Live status indicators and automated email/in-app notification queues.
  • •Discrepancies: Zero budget discrepancies with real-time UACS validation rules.
  • •Verification: DICT PNPKI digital signatures with immutable SHA-256 audit log.

[02] // the workflow

One path from draft to signed plan.

Every document follows the same state machine, so users learn it once and every step leaves an audit trail.

  1. 01 · draft

    7-step wizard

    Proponents build the proposal step by step, with library-driven fields.

  2. 02 · review

    Send for review

    Reviewers comment in context; office users are notified.

  3. 03 · recommend

    Recommendation

    Recommending officials set suggested amounts or return it for revision.

  4. 04 · approve

    Approval

    Approve, reject, or send back, each action logged with its comment.

  5. 05 · sign

    Digital signature

    The generated PDF is signed through an external e-signature service.

  6. 06 · plan

    WFP → PPMP → APP

    Approved work feeds the financial and procurement plans.

Return-for-revision loop: any reviewer can send a document back to the proponent with comments. It then re-enters the flow with its full history intact.

[03] // what's inside

The modules.

Mother Project Proposals

A 7-step guided wizard, review queues per role, comments, return for revision, recommendation with suggested amounts, approval, version history with statistics, and printable zero drafts.

Activity Designs

Multi-step activity designs linked to their proposal, submitted for review, rendered to PDF, signed, and verifiable through a public link with its approval trail.

Work & Financial Plans

WFPs at agency, regional and program level, a merged agency-wide view, approval, and export for reporting.

Procurement planning

PPMP creation, review, approval and revision tracking, with the Annual Procurement Plan generated and grouped from approved PPMPs.

Security & administration

Roles and privileges, account lockout and unlock, forced change of default passwords, user activation, audit logs, maintenance mode, system notifications and in-app issue reports.

Integrations & reference data

Sanctum API tokens with revocation and usage analytics, a document-tracking (DOTS) integration, and 21 reference libraries such as PSGC locations, UACS codes, KPIs, funding sources and signatories.

    $table->uuid('uuid')->unique();
    $table->string('title', 300);

    $table->foreignId('proponent_id')->constrained('users');

    $table->softDeletes();
});

[07] // engineering decisions

Choices that made it work.

01

Signing that can't block the workflow

Signed PDFs come back from the external e-signature service through a server-side proxy, are validated, and are stored against the document. Each approval stage also has an explicit "skip signature" path, so an outage of an external service never stalls approvals.

02

Verifiable documents without exposing IDs

Activity designs get a public PDF and approval-trail link built on Hashids, not raw database IDs. Anyone holding a printed copy can confirm it's genuine, and internal record numbers stay private.

03

Reference libraries instead of free text

Locations (PSGC), account codes (UACS), KPIs, funding sources, procurement modes and signatories live in 21 maintained libraries. Forms pick from them, which keeps data consistent enough to consolidate into agency-wide plans.

04

Operational safety built in

Audit logs record who did what. Accounts lock after repeated failures and can be unlocked by admins. Default passwords must be changed on first login. A maintenance mode with an admin bypass lets administrators take the system offline for updates while still checking it themselves.
