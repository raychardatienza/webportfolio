Building a multi-step form wizard with Laravel, Inertia and React

Long government forms are easier to finish in steps. Here is the pattern I use: one record, validation per step, no skipping ahead, and drafts that survive a closed browser tab.

Raychard Atienza · Oct 2026 · 6 min read

The idea

A proposal form might have seven sections: basics, objectives, beneficiaries, budget, schedule, attachments and review. Put all of that on one page and people abandon it. Split it into steps and you get three wins: smaller validation errors, progress people can see, and drafts saved after every step.

The core decisions:

  • One database record holds the whole form. Each step fills in part of it, and a current_step column remembers the furthest step completed.
  • The server is the source of truth. Every "Next" saves to the database, so closing the tab loses nothing.
  • Validation per step. Each step only checks its own fields.
  • No skipping ahead. Visiting step 5 before finishing step 2 redirects you back.

Routes

// routes/web.php
Route::middleware('auth')->group(function () {
    Route::get('/proposals/{proposal}/step/{step}', [ProposalWizardController::class, 'show'])
        ->whereNumber('step')->name('proposals.wizard');
    Route::put('/proposals/{proposal}/step/{step}', [ProposalWizardController::class, 'update'])
        ->whereNumber('step')->name('proposals.wizard.update');
});

The controller

class ProposalWizardController extends Controller
{
    private const STEPS = 7;

    public function show(Proposal $proposal, int $step)
    {
        $this->authorize('update', $proposal);
        abort_unless($step >= 1 && $step <= self::STEPS, 404);

        // Don't let anyone jump ahead of the furthest completed step
        if ($step > $proposal->current_step + 1) {
            return to_route('proposals.wizard', [$proposal, $proposal->current_step + 1]);
        }

        return Inertia::render('Proposals/Wizard', [
            'proposal'   => $proposal,
            'step'       => $step,
            'totalSteps' => self::STEPS,
        ]);
    }

    public function update(Request $request, Proposal $proposal, int $step)
    {
        $this->authorize('update', $proposal);
        $data = $request->validate($this->rulesFor($step));

        $proposal->fill($data);
        $proposal->current_step = max($proposal->current_step, $step);
        $proposal->save();

        return $step < self::STEPS
            ? to_route('proposals.wizard', [$proposal, $step + 1])
            : to_route('proposals.show', $proposal)->with('success', 'Proposal submitted for review.');
    }

    private function rulesFor(int $step): array
    {
        return match ($step) {
            1 => ['title' => ['required', 'string', 'max:255'], 'program_id' => ['required', 'exists:programs,id']],
            2 => ['objectives' => ['required', 'string', 'min:30']],
            3 => ['beneficiaries' => ['required', 'array', 'min:1']],
            // … one entry per step
            default => [],
        };
    }
}

Keeping the rules in one match makes each step's requirements easy to read. When a step grows, move its rules into a dedicated Form Request.

The React page

Inertia's useForm keeps field state, the submitting flag and validation errors in one place. The route() helper comes from Ziggy.

import { useForm, Link } from '@inertiajs/react';

export default function Wizard({ proposal, step, totalSteps }) {
  const { data, setData, put, processing, errors } = useForm({
    title: proposal.title ?? '',
    program_id: proposal.program_id ?? '',
    objectives: proposal.objectives ?? '',
  });

  const next = (e) => {
    e.preventDefault();
    put(route('proposals.wizard.update', [proposal.id, step]), { preserveScroll: true });
  };

  return (
    <form onSubmit={next}>
      <progress value={step} max={totalSteps} aria-label={`Step ${step} of ${totalSteps}`} />
      {step === 1 && <BasicsStep data={data} setData={setData} errors={errors} />}
      {step === 2 && <ObjectivesStep data={data} setData={setData} errors={errors} />}
      {/* … */}
      {step > 1 && <Link href={route('proposals.wizard', [proposal.id, step - 1])}>Back</Link>}
      <button disabled={processing}>{step < totalSteps ? 'Save & continue' : 'Submit'}</button>
    </form>
  );
}

"Back" is a plain link, not a submit, so people can review earlier steps without tripping that step's validation.

Test the rules that matter

it('does not let users skip ahead', function () {
    $user = User::factory()->create();
    $proposal = Proposal::factory()->for($user)->create(['current_step' => 1]);

    $this->actingAs($user)
        ->get(route('proposals.wizard', [$proposal, 5]))
        ->assertRedirect(route('proposals.wizard', [$proposal, 2]));
});

it('validates only the current step', function () {
    $user = User::factory()->create();
    $proposal = Proposal::factory()->for($user)->create(['current_step' => 1]);

    $this->actingAs($user)
        ->put(route('proposals.wizard.update', [$proposal, 2]), ['objectives' => ''])
        ->assertSessionHasErrors('objectives')
        ->assertSessionDoesntHaveErrors('title');
});

Small things users notice

  • Show "Step 3 of 7" in words, not just a bar. It's clearer and screen readers announce it.
  • Use preserveScroll so a validation error doesn't jump the page to the top.
  • On the last step, show a read-only summary of every section with "Edit" links back to each step.
  • Train users once. Even a good wizard gets adopted faster after a 20-minute walkthrough.
