Public document links without exposing database IDs

A QR code on a printed certificate lets anyone confirm it's genuine. But if that link is /documents/42, you've also told the world how many documents exist and invited people to try 41 and 43. Here are three better options and when to use each.

Raychard Atienza · Oct 2026 · 5 min read

Option 1: Hashids, short and reversible

Hashids turns a number into a short string like x7Lq9RwB2p and back again. You don't need a new database column, and the links stay short enough for a QR code.

composer require hashids/hashids
// app/Support/DocumentHash.php
use Hashids\Hashids;

final class DocumentHash
{
    public static function encode(int $id): string
    {
        return self::hashids()->encode($id);
    }

    public static function decode(string $hash): ?int
    {
        return self::hashids()->decode($hash)[0] ?? null;
    }

    private static function hashids(): Hashids
    {
        // Use a dedicated salt (not APP_KEY), so rotating the app key doesn't break printed links
        return new Hashids(config('services.hashids.salt'), 10);
    }
}
// routes/web.php
Route::get('/verify/{hash}', function (string $hash) {
    $id = DocumentHash::decode($hash);
    abort_if($id === null, 404);

    $document = Document::with('approvals.user')->findOrFail($id);

    return view('documents.verify', ['document' => $document]);
})->middleware('throttle:30,1')->name('documents.verify');

Important: Hashids is obfuscation, not encryption. Anyone who learns the salt can decode every link. Treat the verification page as public and show only what verifying needs: title, status, signatories and dates. Never show private details.

Option 2: a random token, truly unguessable

If the link itself grants access to something sensitive, store a random token instead:

// migration
$table->string('public_token', 40)->unique();

// model
protected static function booted(): void
{
    static::creating(fn (Document $d) => $d->public_token ??= Str::random(40));
}

// route model binding by token
Route::get('/verify/{document:public_token}', VerifyDocumentController::class)
    ->middleware('throttle:30,1');

It costs one indexed column, but there's nothing to decode, and you can revoke a link by regenerating its token.

Option 3: signed URLs, for links that should expire

$url = URL::temporarySignedRoute('documents.download', now()->addDays(7), ['document' => $document]);

Route::get('/documents/{document}/download', DownloadController::class)
    ->middleware('signed')->name('documents.download');

Signed URLs are great for "here's your file, valid for a week" emails. They're too long for a QR code on paper, and they still contain the real ID.

Which one?

NeedUse
Short QR link on a printed document; the page shows public facts onlyHashids
The link grants access to something private, or must be revocableRandom token
Temporary access, sent by emailSigned URL

Putting it on paper

composer require simplesoftwareio/simple-qrcode
{!! QrCode::size(140)->generate(route('documents.verify', DocumentHash::encode($document->id))) !!}

Checklist

  • No sequential IDs in anything printed or shared.
  • The verification page shows the minimum needed to trust the document.
  • Rate-limit the verification route (throttle) so it can't be brute-forced.
  • Log verifications, so you can spot a document being checked unusually often.
  • Keep the salt or token secret out of version control (.env).
